## 1. Why a split licence

The repository is three kinds of work under one copyright:

| Material | Measured in this repository | Why one licence does not fit |
| --- | --- | --- |
| Python reference code | 72 `.py` files under `modules/*/code`, `prerequisites/*/code`, `assessments/` | Readers and instructors expect to copy, run and modify code; a content licence such as CC BY 4.0 is a poor fit for software because it says nothing about patents, and it conflicts with common dependency licences. |
| Prose lessons, labs, rubrics, notebooks | 275 Markdown files, 35 notebooks | A code licence (MIT) would let a third party strip attribution from prose, which is not the intent of an educational text. |
| Synthetic datasets | `code/data/rai_datasets.npz`, `code/gen_samples.npz`, and every in-script generator | Data wants the fewest restrictions possible so students can reuse it in their own projects without asking. |

A split licence — MIT for code, CC BY 4.0 for content, CC0 1.0 for synthetic data — is the
conventional arrangement for a course of this shape. It is a **proposal**, not a legal opinion;
the author may prefer CC BY-NC-SA 4.0 for content if commercial reuse should require permission,
and that choice is compatible with everything below except the "commercial use" clause.

## 2. Proposed arrangement

| Layer | Proposed licence | Scope | Notes |
| --- | --- | --- | --- |
| 1. Original source code | **MIT** | Every `.py` file authored for this course, plus the `tests/` suite and `audit/` scripts | Permissive, patent-neutral, compatible with the BSD/Apache dependencies the course imports. |
| 2. Original educational content | **CC BY 4.0** | Lessons, labs, assessments, notebooks' prose, diagrams authored here, rubrics, `docs/` | Requires attribution and indicates changes. The course is designed to be adapted by other instructors; this is the licence that permits it. |
| 3. Original synthetic datasets | **CC0 1.0** | Data generated by seeded code in this repository (`rai_datasets.npz`, `gen_samples.npz`, in-script generators) | No rights reserved; a student can use the data in a thesis or a product without a licensing question. |
| 4. Third-party materials | **Not covered** — remain under their own terms | Anything not authored here (see §4) | The repository must not claim a licence over material it does not own. |
| 5. External models and datasets | **Not redistributed** — runtime dependencies | Hugging Face checkpoints, scikit-learn's bundled digits, Fashion-MNIST if downloaded | The student accepts the upstream licence at download time; the course only names the model. |

If approved, the mechanical change is small and should be a separate commit:

1. `LICENSE` — MIT text, copyright "Muhammad Nadeem Majeed".
2. `LICENSE-CONTENT` — CC BY 4.0 legal code with a one-paragraph scope note pointing at lessons,
   labs, assessments and notebook prose.
3. `LICENSE-DATA` — CC0 1.0 with a scope note pointing at the synthetic data and generators.
4. A "Licence" section in `README.md` summarising the three layers and linking each file, plus a
   short "Third-party material" paragraph stating that §4 items are excluded.
5. Update the FAQ answer that currently says permission is required, so the FAQ and the licence
   agree. That answer is the only licensing statement in the repository today and would
   otherwise contradict the new files.

## 3. What the inspection found

- **No `LICENSE`, `COPYING` or `LICENCE` file** exists at the root or in any module.
- **No copyright line** in `README.md`; the only statement is the FAQ answer requiring permission.
- **No third-party code vendored.** Every module imports installed packages (`numpy`, `scipy`,
  `torch`, `gymnasium`, `transformers`) rather than copying their source.
- **No bundled third-party datasets.** The two `.npz` files are generated by this repository's
  own seeded code; `dataset_cards.json` records `licence: CC0-1.0` and the known limits of each
  synthetic set. Real datasets (Iris, Fashion-MNIST, sklearn digits) are referenced or loaded
  through a library, not committed.
- **No images or diagrams from third parties.** Diagrams are generated from text (Mermaid) or
  drawn by course code; no binary image assets are committed.
- **No model weights committed.** Checkpoints are named and downloaded at runtime.
- **Attribution statements exist** for datasets in lesson and lab text, and in
  `modules/M07-neural-networks-and-deep-learning/code/deep_data.py`, which names Fashion-MNIST
  and its MIT licence at the point of use. Coverage of model licences across M07/M11 is
  uneven — see §6.

## 5. Outbound notices the course should keep

- Rubrics and labs that name a real company, product or incident (for example the case studies in
  M13) describe them for teaching; they do not imply endorsement.
- `resources/` paraphrases papers. Where a lesson quotes a definition closely, the citation is in
  the text; no long excerpts are reproduced.
- Synthetic data is labelled synthetic wherever it is used, and `dataset_cards.json` states the
  intended use and known limits. That labelling must survive any relicensing.

## 6. Gaps to close before the licence is applied

1. **Model licences are not stated uniformly.** M11 names several checkpoints without a licence;
   add one clause per checkpoint rather than a blanket claim.
2. **The FAQ contradicts an open licence** and must be rewritten in the same change as the
   licence files.
3. **No copyright holder line** exists for the author; the MIT and CC BY notices need a name and a
   year, and the year must be the actual year of publication.
4. **Notebooks mix code and prose.** The proposal treats notebook prose as content (CC BY 4.0) and
   notebook code cells as code (MIT); that split should be stated in the README so a reader is not
   left to infer it.
5. **Contributions.** If the repository ever accepts outside contributions, it needs a contributor
   licence agreement or a DCO; nothing today addresses inbound licensing.

## 7. Recommendation

Adopt the three-layer split in §2, apply it as one reviewed commit with the README and FAQ edits,
and keep §4 as an explicit exclusion list rather than attempting to relicense anything the author
does not own. Until that commit is approved, this document is the only statement of intent and
**grants no rights**.

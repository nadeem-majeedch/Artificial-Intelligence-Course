# Licensing and References Audit — Phase 23

**Scope:** datasets, model weights, third-party code, images and diagrams, external references, privacy,
security exercises and high-stakes framing.

## 1. Datasets

**No third-party dataset is redistributed in this repository.** Every dataset a student is asked to use is
generated in code, with one exception noted below.

| Module | Data source | Licence position |
| :--- | :--- | :--- |
| M06 | `datasets.py` synthetic tables; scikit-learn `load_digits` for a demonstration only | scikit-learn's bundled digits data is BSD-3-Clause and is used through the installed package, not copied into the repo |
| M07 | synthetic image/sequence tensors; optional real counterparts named, not bundled | no redistribution |
| M08 | toy corpus written in the module; optional `distilbert-base-uncased` download | corpus is course-authored; model licence below |
| M09 | **all images generated** by `vision_core.py` (leaves, signs, detection scenes, road masks) | course-authored synthetic data, free to use and modify with attribution; no dataset licence attaches because no dataset is downloaded |
| M10 | gridworlds, cliff walking and CartPole built in code (Gymnasium optional) | course code |
| M11 | digits for VAE/GAN/diffusion; synthetic QA pairs; optional HF models | model licences below |
| M12–M14 | scripted scenarios and synthetic records | course-authored |

The M09 module page, all four M09 labs and the notebook say explicitly that the images are synthetic and
that "no licence attaches to the data" because nothing is downloaded. The labs that reference a real
counterpart (plant disease, traffic signs, Fashion-MNIST, UCI student performance) name it, state its
licence where relevant (for example UCI student performance, CC BY 4.0) and require the student to check
the terms before substituting it. That is the correct handling: reference without redistribution.

## 2. Model weights

No weights are committed. Two families are downloaded at runtime by optional code paths:

| Model | Where | Licence | Handling |
| :--- | :--- | :--- | :--- |
| `distilbert-base-uncased` | M08 `embeddings.py`, `seq_models.py`; M11 notebooks | Apache-2.0 | downloaded to the Hugging Face cache on first use; absence is detected and reported, not assumed |
| `sentence-transformers/all-MiniLM-L6-v2` | M11 `rag.py` | Apache-2.0 (stated in the module docstring) | same |
| small causal LMs for the LLM labs | M11 `llm_gen.py`, `lora.py`, `prompts.py` | per model card | the code checks availability and falls back to a local toy model |

The M09 module is explicit that it uses **no** pretrained backbone, and that a student who substitutes one
must record that model's licence and its training-data provenance. This is a stronger position than most
courses take.

## 3. Third-party code

No vendored libraries, no copied Stack Overflow snippets, no licence-bearing source files. All Python under
`modules/*/code/` is course-authored; third-party packages are imported, not copied. Where an algorithm is
a textbook standard (Dijkstra, CART, backpropagation, PPO), the implementation is written for teaching and
the lesson cites the source of the idea rather than copying code.

## 4. Images, diagrams and notebooks

- All figures are generated by code (matplotlib) or are Mermaid diagrams in Markdown (18 files). No bitmap
  assets are stored, so no image licence attaches.
- Notebook outputs contain plots generated locally from the same seeds, not screenshots of third-party work.
- No copyrighted screenshots, book scans or paper figures appear in the repository.

## 5. External references

Reference domains, counted across all Markdown: `arxiv.org` (60), `docs.python.org` (14),
`huggingface.co` (14), `github.com` (11), `numpy.org` (8), `pandas.pydata.org` (8), `scikit-learn.org` (7),
`matplotlib.org` (5), plus standards bodies and textbooks in the reading lists.

References are used for further reading, not as substitutes for explanation. No claim in the lessons depends
on a link resolving; each reference is supplementary to material that is stated in the page. Links were
checked for internal consistency (see §7); external URLs were **not** fetched in this audit, so their
current availability is unverified.

## 6. Privacy, security and high-stakes framing

- **Privacy:** every record about a person (students, applicants, loan applicants, patients in examples) is
  synthetic. No personal data is included, no scraping, no real identifier. The M13 privacy lesson teaches
  membership-inference style attacks against a locally trained toy model, not against a real service.
- **Security exercises:** prompt-injection and adversarial-example labs run against the course's own toy
  systems and require the student to write a scope statement. No lab instructs an attack on a third-party
  system, and none includes exploit code for real software.
- **High-stakes qualification:** M09 states that synthetic vision results say nothing about clinical,
  agricultural or safety-critical performance and that no model here is clinically validated. The M04
  advising project is explicitly a synthetic teaching system, not a university admissions or advising
  service. M13 requires students to name the decision a model supports and the cost of its errors.
- **Missing:** there is no repository-level `LICENSE` file and no `CITATION.cff`. That is an owner decision
  (the repository may be private or unlicensed by intent), and it is recorded here rather than silently
  added, because choosing a licence on the owner's behalf would be inappropriate.

## 8. Verdict for this audit

The repository is unusually clean on licensing: it redistributes no data, ships no weights and stores no
images, so the usual attribution problems do not arise. The gaps are administrative (no `LICENSE`, no
`CITATION.cff`, no per-page copyright statement) and verification (external links not fetched). No privacy
or security-exercise problem was found.
